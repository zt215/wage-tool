# 员工工资申报转换工具

把「员工申报情况汇总表」里的工资、各种保险，按「样表」的格式转换成一张完成表。
界面操作，字段自动识别，规则手工确认，输出时复制样表、数据从**第 4 行**开始写。

---

## 一、怎么运行

按方便程度选一种：

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| **独立程序（推荐）** | 双击 `dist\员工工资申报转换工具.exe` | 换台电脑直接能跑，不用装 Python |
| 一键启动 | 双击 `启动工具.bat` | 已经打包过，或本机装了 Python 环境 |
| 源码运行 | 见文末「从源码运行」 | 要改代码 |

`启动工具.bat` 会自己判断：有 exe 就开 exe，没有就找 `.venv` / `.buildenv` 里的 Python 跑源码。

## 二、界面操作五步

窗口分成 **5 个页签**，一页只放一块内容，不会挤在一起。底部有「上一步 / 下一步」按钮可以翻页。

```
① 数据源 | ② 转换规则 | ③ 输出设置 | ④ 结果预览 | ⑤ 日志
```

右上角有「检查更新」，右下角状态栏永远显示最新一条消息。
**所有勾选项和字体设置都会自动记住**，下次打开还是上次那样（见第七节）。

### ① 数据源（加初始表 + 样表）
**添加初始表** —— 选 `2023年员工申报情况汇总.xlsx` 这类文件。
程序会自动识别出这是「按人分块」的结构（姓名行 → 人员信息行 → 表头行 → 数据行），
左上列出识别到的全部字段，顶部显示结构与记录条数。

**添加样表** —— 选样表文件。默认规则：

- 工作表：`sheet1`
- 表头行：第 `1` 行
- 数据起始行：第 `4` 行

这三个都能在界面上改（改了会重新识别）。
样表里那句重名规则说明也会自动读出来显示在黄色框里。
两张表都加好后会自动跳到「② 转换规则」。

### ② 转换规则（手工确认）
逐行核对自动识别出来的建议规则：

| 列 | 含义 |
| --- | --- |
| 启用 | 勾掉就不输出这一列 |
| 样表字段 | 要给样表的哪个列赋值 |
| 规则类型 | 求和 / 取首个 / 取最后一个 / 计数 / 固定值 / 自动编号 / 不输出 |
| 初始表字段（相加） | 参与计算的初始表字段，**可以多个，多个就是相加** |
| 筛选条件 | 只汇总满足条件的数据行 |
| 状态 | 待确认 / 已确认 / 已停用 / 无对应字段 |

**双击任意一行**可以打开详细编辑框，里面能勾选多个初始表字段、设筛选条件，
并且实时显示前 3 个人的计算结果，确认没问题再点确定。
全部核对完点「全部确认」。

两种规则形态都支持：

- **一个对一个**：`养老保险` ← 初始表的 `基本养老保险费`
- **多个相加等于一个**：勾选多个字段，例如 `应发工资` ← `收入` + `奖金` + `补贴`

工资/奖金/其他要拆开的话，就靠**筛选条件**：
`应发工资` ← `收入`，筛选 `所得项目 = 正常工资薪金`；
`奖金` ← `收入`，筛选 `所得项目 = 全年一次性奖金收入`。
不想拆就把筛选清空，全部收入汇总到一个字段。

### ③ 输出设置
上半部分是输出选项：

- **启用重名规则**：同上，同名的人自动改成 `张1三`、`张2三`（数字插在名字中间，不放在头尾）。
  默认插在「第一个字之后」；三字名想插在中间可以改成「最后一个字之前」。
- **期间文本自动转成日期**：把 `2023年12月` 转成真正的日期值。
- **清空样表第 2 行示例数据**：样表第 2 行是「演示号」这行假数据，勾上就清掉。

下半部分是**输出格式**：

- 默认**不勾**，数据完全沿用样表里那一行的格式，什么都不动。
- 想改就勾上「应用自定义字体 / 字号 / 颜色」，然后设：
  字体（下拉选，全系统字体）、字号、**字体颜色**（点按钮弹调色板）、加粗、
  水平对齐、「表头行一起改」。
- 下面那行会**实时预览**效果。
- 只改字体和对齐，**样表的边框、数字格式不会被破坏**。

设好点「预览转换结果」看一眼，没问题再点「输出完成表」选保存位置。

输出逻辑：**复制一份样表** → 表头行、说明文字原样保留 → **从第 4 行开始**逐行写入数据。

### ④ 结果预览
转换出来的表格，一人一行，列和样表一致。预览最多显示 200 行。

### ⑤ 日志
每一步的操作记录、识别了几条规则、输出到哪、有没有报错，都在这页。
底部状态栏始终显示最新一条。

## 三、命令行批量转换（可选）

```
员工工资申报转换工具_v1.2.1.exe --convert --source 汇总表.xlsx --sample 样表.xlsx --out 完成表.xlsx
```

其他参数：`--sheet` 工作表名、`--header-row` 表头行、`--start-row` 起始行、
`--no-rename` 关闭重名规则、`--keep-example` 保留示例行。
输出格式：`--font 黑体 --font-size 12 --color "#C00000" --bold --align center --fmt-header`。
执行结果同时写到 `完成表_报告.txt`。

其他命令：

```
...exe --version                                   查看版本号
...exe --check-update                              检查更新（结果写「检查更新结果.txt」）
...exe --selftest                                  程序自检（结果写「自检结果.txt」）
```

## 四、检查更新（用 GitHub Releases，不用自己服务器）

右上角有「检查更新」按钮。**启动时也会自动查一次**，如果发现新版本，
直接弹一句「发现新版本 v1.3.0，是否现在更新？」——点「是」就开始下载替换，
点「否」就在按钮上留个提示，下次再升。

手动点「检查更新」也是一样，只有三种结果：

| 情况 | 界面表现 |
| --- | --- |
| 有新版本 | 一行黄字「发现新版本 v1.3.0（36.8 MB），点「立即更新」自动升级」+ 更新说明 |
| 已是最新 | 一行绿字「已经是最新版本（v1.2.1），不用更新」，没有别的按钮 |
| 连不上 | 一行红字说明原因（鼠标悬停或下面方框里有完整报错） |

更新地址平时藏在小链接「更新地址」后面，**不用管**，换更新源时再点开改。

更新源用的是你的 GitHub 仓库：

```
https://github.com/zt215/wage-tool
```

### 为什么不用 version.json 了

软件会**自动识别地址**：写成 GitHub 仓库地址时，它直接调 GitHub Releases API
拿「最新 release」的版本号和附件，**不需要你额外维护任何清单文件**。
发新版只要在仓库上建一个 Release、把 exe 传上去就行。

GitHub 会顺带给出附件的 sha256，所以下载完整性校验照样有。

> 想换回自己的服务器也行：地址栏改成 `http://IP:端口/update/version.json` 照样认。
> **地址栏支持写多行**，会按顺序依次尝试，前面连不上自动试下一个
> （以后想加备用源，换行写上就行）。

### 前置：仓库必须至少有一次提交 ⚠️

GitHub 的 Release 是打在 tag 上的，tag 必须指向一个 commit。
**空仓库（0 个提交）根本建不了 Release** —— 这也是刚建好仓库时
在仓库页面上看不到 Releases 入口的原因。

解决：双击 **`推送到GitHub.bat`**，把源码推上去（第一次会弹 GitHub 登录）。

> 仓库里**不会**包含含员工姓名/身份证号的 Excel 和截图 —— `.gitignore` 已经挡住了，
> 只有源码和脚本。推送前可以用 `git status` 确认一下。

### Release 在哪儿

```
https://github.com/zt215/wage-tool/releases
```

仓库有内容之后，仓库首页**右侧栏**也会出现 `Releases` 入口。
（空仓库时右侧栏不显示这个，所以刚建好时找不到是正常的。）

### 怎么发新版（一键）

1. 改 `core/version.py` 里的 `__version__`，比如 `1.2.0` → `1.3.0`
2. 双击 **`打包exe.bat`** —— 生成 `员工工资申报转换工具_v1.3.0.exe`
3. 双击 **`发布到GitHub.bat`** —— 自动建 Release（tag = `v1.3.0`）并把 exe 传上去
4. 完事。用户点「检查更新」就能看到新版并一键升级

**第一次**用需要一个 GitHub Token。不知道去哪儿拿？双击 **`获取Token.bat`**，
它会直接帮你打开新建页面。手动操作的话：

**【推荐】经典 Token，3 步**

1. 浏览器打开 https://github.com/settings/tokens/new
   （或从 https://github.com/settings/tokens 点右上角
   `Generate new token` → `Generate new token (classic)`）
2. Note 填个名字（如 `wage-tool`），Expiration 选有效期
   （建议 90 天；嫌麻烦可以选 `No expiration`）
   权限列表里**勾上第一项 `repo`**（勾上后子项会自动全选）
3. 拉到最底下点绿色的 **Generate token**

页面上会出现一串 **`ghp_` 开头**的字符，**复制它**。

> ⚠️ **这串字符只在生成时显示一次**，关掉页面就再也看不到了。
> 丢了只能重新生成。之前提示"token 过期"多半就是有效期到了或者换过一次。

**【备选】细粒度 Token（更安全，步骤多一点）**

1. 打开 https://github.com/settings/personal-access-tokens/new
2. Token name 填 `wage-tool`，Expiration 选有效期
3. Repository access 选 `Only select repositories` → 勾上 `wage-tool`
4. Repository permissions → 找到 **Contents** → 改成 **Read and write**
5. 点 **Generate token**，复制 `github_pat_` 开头那串

Token 只存本机 `tools/github_token.txt`（已在 `.gitignore` 里），不会上传。

命令行也能发：

```bat
.buildenv\Scripts\python tools\publish_github.py --notes "1. 修复xx\n2. 新增yy"
.buildenv\Scripts\python tools\publish_github.py --draft      :: 发草稿先看看
.buildenv\Scripts\python tools\publish_github.py --clear-token :: 忘掉本机保存的 Token
```

> 仓库必须是 **Public**。私有仓库的话软件端不带 token 读不到 Release。

> 💡 **附件名被弄丢了也没关系。** 用网页上传时，浏览器会把中文附件名截断，
> 变成 `_v1.2.2.exe` 这种（**这是已知现象，你之前两次发布都中招了**）。
> **不影响使用** —— 软件判断版本只看 tag 名；下载后在本机也一律存成
> 「员工工资申报转换工具_v版本号.exe」，不会跟着附件名走。
>
> 用 `发布到GitHub.bat` 发布时会**自动检查并把附件名改回来**，
> 所以走脚本发的包不会有这个问题。

### 不想折腾 Token？网页手动传也行（Plan B）

完全不碰命令行，5 步搞定，效果一模一样：

1. 打开 https://github.com/zt215/wage-tool/releases
2. 点 **Draft a new release**
3. **Choose a tag** 里输入 `v1.2.1`（**一定要带前面的 v**，而且要跟 `core/version.py` 里的号对上），
   然后点「Create new tag on publish」
4. **Attach binaries** 把 `dist\员工工资申报转换工具_v1.2.1.exe` 拖进去
   （文件较大，传完等进度条走完，**必须看到文件名出现在附件列表里**）
5. 填个标题，点 **Publish release**

完事。软件端认的就是 tag 名 + 附件，跟你从哪儿传的没关系。

### Token 常见问题

程序会先做**本地体检**：明显不像 Token 的（比如把仓库网址粘进去了）会当场打回来，
**不会存下来**，所以不会出现"存了个错的、以后一直失败"的情况。

| 现象 | 原因 / 办法 |
| --- | --- |
| 提示「这看起来是仓库网址，不是 Token」 | 粘错东西了。Token 长这样：`ghp_AbCd...`，双击 `获取Token.bat` 去生成 |
| 提示「Token 无效或已过期（401）」 | Token 过期或被撤销了。重新生成一个，程序会自动删掉旧的并让你重输 |
| 提示「权限不够（403）」 | classic token 忘了勾 `repo`；fine-grained 忘了给 `Contents: Read and write` |
| 提示「仓库读不到（404）」 | fine-grained token 的 Repository access 里没勾上 `wage-tool` |
| 想彻底换一个 Token | 双击「发布到GitHub.bat clear-token」，或直接删 `tools\github_token.txt` |
| Token 忘了复制就关了页面 | GitHub 不会再次显示。只能重新生成一个（旧的可以顺手删掉） |

> classic token 的 `No expiration` 选项可以一劳永逸，但安全性差一点；
> 选 90 天的话到期要换一次，程序会提示 401 并让你重新填。

### 文件名的约定

打包出来的程序、Release 附件、更新后用户电脑上的程序，
**文件名统一是「员工工资申报转换工具_v版本号.exe」**。

更新的时候：

```
更新前： 员工工资申报转换工具_v1.2.1.exe            ← 正在运行
          ↓ 更新
更新中： 员工工资申报转换工具_v1.2.1.exe.old.exe    ← 旧版改名让位
         员工工资申报转换工具_v1.3.0.exe            ← 新版落地并启动
          ↓ 下次启动时自动清理
最终：   员工工资申报转换工具_v1.3.0.exe
```

> ⚠️ 因为文件名带版本号，更新后**桌面上的旧快捷方式会失效**。
> 删掉重新建一个指向新文件的就行；或者用 `启动工具.bat` 启动，
> 它会自动找 dist 里最新的那个 exe。

### 网络出口会自动切换

国内访问 GitHub 有时要走代理、有时要直连（企业内网尤其）。
软件会**两种都试**，哪个通用哪个并记住，下次直接用。代理开着、关着都不影响。

### 还有一个坑：github.com 会被墙

国内 `github.com` 经常整站连不上（`api.github.com` 反而是通的）。
而 Release 附件的默认下载地址正好在 `github.com` 上，**用户会下不动**。

所以软件下载时**优先走 GitHub 的 API 接口**
（`api.github.com/.../releases/assets/...`），它会直接跳到
`release-assets.githubusercontent.com`，**完全绕开 github.com**；
万一 API 那条也不通，再自动退回普通地址重试一次。

> 结论：`api.github.com` 通、`github.com` 不通的情况下，检查更新和下载**都没问题**。

### 更新是怎么完成的

下载到临时目录 → 比对 sha256（GitHub 会给；不一致就放弃）→
把正在运行的旧程序**改名**成 `.old.exe`（Windows 上运行中的 exe 不能覆盖但能改名）→
新版以**新版本号的文件名**落地 → 启动新版、退出旧版 → 下次启动自动删掉那个 `.old.exe`。

### 命令行排查

```
员工工资申报转换工具_v1.2.1.exe --check-update
```

结果写到同目录的「检查更新结果.txt」，能看到走的是直连还是代理、版本号、
下载地址、sha256，方便排查连不上的问题。

## 五、设置存在哪（记住上次的勾选）

配置固定放在这里：

```
%APPDATA%\员工工资申报转换工具\settings.json
```

也就是 `C:\Users\你的用户名\AppData\Roaming\员工工资申报转换工具\settings.json`。

> ✅ **程序旁边不会生成任何文件。** 程序放哪个文件夹，那里就只有程序本身，
> 不会冒出 `settings.json` 之类的零碎东西。
>
> 早期版本会在 exe 旁边写 `settings.json`，新版本启动时会**自动把配置搬过来
> 并把外面那个删掉**，设置不会丢。

保存的内容：

- 输出选项：重名规则、插入位置、期间转日期、清空示例行
- 输出格式：是否启用、字体、字号、颜色、加粗、对齐、表头行是否一起改
- 检查更新地址
- 上次用的初始表 / 样表路径（选文件时直接定位到那个文件夹）
- 窗口大小和位置

想恢复默认：删掉上面那个 `settings.json` 再打开程序即可。

## 七、从源码运行 / 重新打包

本目录里已经有两个现成的环境，一般不用再建：

- `.buildenv` —— 运行 + 打包都用它（PySide6-Essentials + openpyxl + pyinstaller）
- `.venv` —— 早期调试留下的，装的是完整版 PySide6（含用不到的 WebEngine，约 678MB），
  确认 `.buildenv` 能用之后可以整个删掉

```bat
:: 直接跑源码
.buildenv\Scripts\python main.py

:: 程序自检
.buildenv\Scripts\python main.py --selftest

:: 重新打包（双击 打包exe.bat 也行）
.buildenv\Scripts\python -m PyInstaller --noconfirm --clean build.spec

:: 万一环境没了，重建：
python -m venv .buildenv
.buildenv\Scripts\pip install PySide6-Essentials openpyxl pyinstaller
```

## 八、常见问题

**识别出来的字段不对 / 没识别到？**
点「自动识别字段」重来一次，或双击那一行手工指定。工伤保险、生育保险这类
初始表里根本没有的列，会自动标成「不输出」，不会被乱猜成别的字段。

**一个人有多行，输出几行？**
一个人一行，同一个人 12 个月 + 年终奖的数据按规则汇总（求和）。

**同名的两个人会被合并吗？**
不会。按「姓名 + 证件号码」分组，两个张三各自成行，再按重名规则改名区分。

**输出后能不能直接用？**
能。输出的是样表的副本，表头、格式、说明文字都在，只有第 4 行往下是新数据。

**上次勾的那些选项，下次打开又变回默认了？**
现在不会了，会自动记住（见第五节）。如果还是恢复默认，说明 `settings.json`
写不进去——看看程序是不是放在 `C:\Program Files` 这种需要管理员权限的目录，
换个目录放就行，程序会自动退到 `%APPDATA%` 下存。

**改了字体颜色，输出的表格边框/数字格式会被搞乱吗？**
不会。只覆盖字体和对齐，边框、数字格式、列宽都保留样表原来的。

**点「检查更新」提示连不上怎么办？**
先在浏览器打开 `https://github.com/zt215/wage-tool/releases` 看看能不能访问。
- 打不开 → 网络问题，挂上你的代理再试；软件自己会试「直连」和「走系统代理」两种，
  哪个通用哪个，不用手动配。
- 能打开但软件提示「没有找到已发布的 Release」→ 仓库上还没发过版本，
  或者仓库是私有的（要改成 Public）。
- 想自己排查，命令行跑一次 `员工工资申报转换工具_v1.2.1.exe --check-update`，
  结果写在同目录「检查更新结果.txt」，能看到卡在哪一步。

**「生成更新包.bat」还要用吗？**
只在你想把包放自己服务器（不走 GitHub）时才用。走 GitHub 用 `发布到GitHub.bat` 就行。

**当前装的是哪个版本？**
窗口标题、右上角、状态栏右下角都写着版本号；程序文件名上也带版本号。

**更新后桌面快捷方式打不开了？**
因为文件名带了版本号，更新后文件名变了，旧快捷方式指向的文件已经不在。
删掉快捷方式，右键新文件「发送到 → 桌面快捷方式」重建一个就行。

**更新到一半失败了怎么办？**
下载的文件会先做 sha256 校验，不一致就不替换，旧的程序不会丢。
万一替换过程中出错，程序会自动把旧版改回来，并告诉你新文件下载在哪，可以手动替换。
